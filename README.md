# whyboard · ecommerce

The second demo app for [**whyboard-core**](https://github.com/mzubairhassan18/whyboard-core):
an AI detective for your store's revenue.

Drop a CSV of orders. Whyboard writes read-only SQL against it — splitting revenue by
product, channel, cohort and discount — tests its own hypotheses, then tells you why
the number moved, with a confidence level, the caveats, and every query it ran.

**Live:** https://whyboard-ecommerce.vercel.app
(custom domain `ecommerce.whyboard.app` once DNS points at the project)

---

## How it works

```
CSV ──▶ CSVAdapter (in-memory libSQL) ──▶ Whyboard (ecommerce template)
                                              │
                            detective: grok-4-1-fast-reasoning
                            ├─ 9 read-only tools (SQL, breakdowns, trends, correlation)
                            └─ report_findings → structured findings
                                              │
                            storyteller: grok-4.6
                            └─ streamed markdown story
```

- `app/api/analyze` loads the CSV, computes the KPI strip (revenue, orders, AOV, repeat
  rate) and returns suggested questions.
- `app/api/chat` streams the investigation as Server-Sent Events: `thought`, `tool`,
  `tool-result`, `answer-delta`, `done`, `error`.
- The UI renders the detective's live case file (with the SQL it actually runs) while the
  story types itself out.

Every request gets a fresh in-memory database. The CSV is never written to disk, never
stored in a bucket, and dies with the response.

## The sample store

`public/sample-orders.csv` holds **909 orders across six months** (April–September 2026),
generated by `scripts/generate-sample.mjs` with a fixed seed. September is engineered to
be a real puzzle:

- revenue falls 30% ($48.2k → $33.6k) while average order value **rises** 12%;
- paid-social orders collapse from 59 to 16 after the summer promo ends;
- the flagship Aurora Lounge Chair gets a price increase and loses two thirds of its units;
- the customer count falls, but returning-customer behaviour does not.

The honest answer is a traffic problem plus one product — not a retention problem.

## Run it locally

```bash
npm install
cp .env.example .env.local   # add one key
npm run dev
```

Open http://localhost:3000 and click **"Try the sample: 909 orders"**.

| script | what it does |
| --- | --- |
| `npm run dev` | Next.js dev server |
| `npm run build` | production build |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run lint` | ESLint |
| `npm run verify` | pipeline smoke test with mock models — **no API key needed** |

`npm run verify` uses the exact `openWorkspace` helper the routes use, against the sample
CSV, with `MockLanguageModelV4` models. It asserts the schema, KPI strip, stream event
order, SQL trail and findings hand-off.

## Configuration

One of these, depending on the provider:

| variable | provider | default models |
| --- | --- | --- |
| `XAI_API_KEY` | Grok (default) | `grok-4-1-fast-reasoning` / `grok-4.6` |
| `OPENAI_API_KEY` | OpenAI | library defaults |
| `AI_GATEWAY_API_KEY` | Vercel AI Gateway | library defaults |

The provider is auto-detected by whyboard-core in that order.

## Limits

- 1.5 MB / 25,000 rows per CSV.
- Questions capped at 500 characters.
- Read-only: whyboard-core rejects anything that is not a single `SELECT`/`WITH`.
- No storage, no accounts, no analytics.
